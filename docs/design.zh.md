# Eyot 产品设计

给人读的产品设计：它是什么、为什么这样切、远期故意留白什么。名词释义在 [`terminology.zh.md`](terminology.zh.md)。技术怎么落地、和代码是否一致，见 [`architecture.zh.md`](architecture.zh.md)。工程规格仍以 `.omo/evidence/audit-product-design.md` 为准；命名决策以 `.omo/evidence/v5-rename-decisions.md` 为准。

---

## 1. 这是什么

Eyot 的目标句是 **harness for harness**：它调度的不是一排聊天机器人，而是一组 **按角色切开的 harness**。每一只后裔都是一个 **harness agent 入口**——带着这个角色需要的能力 / 基因，harness 结构（循环、熔断、notepad、subagent 策略、始祖镜像）也按这类任务来装，让它自己就能把角色份内的一串活做完。Eyot 外层负责组网、投递、观测、把经验写回去。

人在里面创生角色、给角色一个会记得事的身份、把身份落到正在跑的后裔上，在领地地图上调度这些 harness，再把跑出来的经验写回去。

名字来自江心洲：E·Y·O·T = Entity · Yoke · Organization · Topology。一块能站住的岛，不是一条随聊随丢的对话。

聊天工具每次打开都是新的。Eyot 要合上它们合不上的三件事：

| 环 | 聊天工具 | Eyot |
|---|---|---|
| **身份** | 一次回复 | 始祖 → 血脉 → 后裔，一层比一层具体 |
| **记忆** | 窗口里那几轮 | 记忆挂在血脉上，后裔死了身份还在 |
| **协作** | 一对一，或全场广播 | 生境 + 兽道近邻 + 信号塔 + 能看见的地图 |

它不是更大的提示词、不是 Copilot、不是无代码搭建器、也不是把 nodeskclaw 整座六注册表平台再抄一遍。默认可以只有一座大陆、一个区域、一个生境；多租户是真的，但不是使用门槛。

**谁用（现在）**：调度一小队长期干活的角色 harness、需要看得见状态、需要经验留下的操作员。真人永远是操作者；始祖 / 血脉 / 后裔都是 AI，不和人平级。

**谁用（远期，见 §10.3）**：还可以把权分出去——提单人只交工单，不必进领地地图。星球中枢按工单生成并部署一套网络，把需求交给这片生境的小脑，其它角色 harness 做 loop engineering，做完由小脑回一个结论。

## 2. 从哪来，为什么不照抄

产品逻辑来自 **nodeskclaw**（身份、近邻、部署），重建时故意 **做深不做宽**：单租户能用、Portal 极简、视觉优先。

对照三个已知结构性缺陷，Eyot 的切法是：

1. **身份和身体分开。** 原型里一个身份绑死一个运行体，换项目就得再造一个「人」。所以血脉是身份，后裔是这一次跑起来的身体；同一条血脉可以在同一区域的不同生境里各有一个后裔。
2. **近邻，不要总线。** 原型用扁平消息日志拼上下文，拓扑门形同虚设，规模一大上下文就被污染。所以消息只走兽道上的邻居，不搞生境级广播。
3. **选角色，不选引擎。** 原型在创建时逼人挑 OpenCLaw / Hermes。所以人挑的是始祖（狐狸、海狸……）；runtime 是实现细节，对模型只说「你是谁、怎么干活」，不把 Eyot 产品说明书塞进 prompt。

另外两层也要分清，后面所有远期协议都踩在这上面：

- **外层 = Eyot（harness for harness）**：Portal、组网、兽道投递、信号塔、部署、可观测。它调度的对象是一只只角色 harness，不是「再做一个更好用的 senpi 给操作员当 IDE」。
- **内层 = 后裔（角色 harness）**：每个后裔是一个 **harness agent 入口**。循环工程（Boulder、熔断、notepad、continuation）装在这只后裔里，并且按始祖 / 角色特化。驱动循环的 runtime 首选沙箱 **pi**。Senpi / oh-my-openagent / oh-my-pi 是这一层的同类产品面（单操作员、单 harness），不是 Eyot 外层的定位，更不是「把 pi 叫成 Senpi CLI」。

容易读错的旧说法：「Workspace ≈ 更灵活的 senpi」。那是在说 *内层循环工程* 要对齐并超过那一族，不是说 Eyot 整座控制台等于一个 senpi。Eyot 要做的是把很多只这样的 harness 编成一张网。

## 3. 地方和生命是两根轴

不要把租户层级和身份层级揉成一张表。

**地方**管隔离和场景：平台（逻辑控制面，不是业务表）→ **大陆**（租户）→ **区域**（场景分区）→ **生境**（这条工作流）。

区域是 `coding` / `social-media` 这种**业务场景**，不是 dev / staging / prod。血脉住在区域里，正因为身份和记忆应该跟着场景走，而不是跟着某一个具体工作流走——公众号和小山书可以共用一条「内容」血脉，Eyot API 和 Portal 可以共用一条「编码」血脉。

**生命**管角色长成什么样：**始祖**（业务无关的原型，也是这类任务最合适的 harness 骨架）→ **血脉**（这个场景里的谁 + 记忆 + 自己的基因/能力）→ **后裔**（此刻在哪个生境里跑的那只角色 harness）。

后裔不是「通用 agent 再配一句人设」。创生时绑定的能力 / 基因要 **够这份角色把一串任务做完**；不够就是产品没装好，不是让它去全场找人帮忙补洞。pod 内 subagent 只给这份角色当模块，不另占地图。

约束来自寻址：对话里 `@slug` 指血脉，所以同一生境同一血脉最多一个活跃后裔。职级轴（浅识者 / 深潜者）已经拆掉——删职级之后，提及一条还没有后裔的血脉，统一创生持久后裔并沉淀记忆，不再分「热加载实习生」。

**在场**不是第三种业务实体。画布上的节点是 Membership：智人（真人）或生物（绑着后裔），互斥。兽道连的是在场，不是「再连一种走廊锚点」（CorridorNode 已去掉）。

## 4. 身份为什么长成这样

### 4.1 真源在绑定上，不在第二份 JSON

始祖和血脉的能力以 **基因 / 能力的外键** 为准。禁止在表里再塞一份 skills / tools / commands / 大块 runtime_config 当第二真源——那是 nodeskclaw 基因形态爆炸之后 Eyot 要躲开的坑。生物基因的打包走 manifest 内联，运行时只读展开；和「多条能力合成一条基因」是同一套序列化。

血脉可以在始祖之上增删自己的绑定。覆盖写在绑定层，并且 **可以蜕变写回**，否则经验闭环是假的。

### 4.2 五个始祖，不是十一个岗位

判定标准只有一句：**要不要长久记忆。**

要记忆、要占地图、要有名字的，做成始祖（狐狸 / 海狸 / 麻雀 / 郊狼 / 狮子）。只干一趟就结束的（意图分析、读架构、质检、探索、外搜、看图）降成后裔 pod 内部的 subagent 能力：不命名、不占拓扑、不进 Tunnel、不进记忆蒸馏链。经验如果有，回流到叫它的那条血脉。

这是为了避免「拓扑上站着一排顾问，却没有身份可积累」。域模型里执行体只有一种：后裔。

始祖同时是 **镜像薄层 + manifest**：共享 base + 五个动物层，避免镜像爆炸。选 runtime 只换引擎层，始祖镜像封的是内容资产。五个始祖不是五套皮肤——狐狸偏谋划、海狸偏把活做完、麻雀偏快、郊狼偏长程、狮子偏委派把关——各自的 harness 结构（命令、工具、subagent 策略、循环习惯）按这类任务来装。

### 4.3 知识分成「需要」和「拥有」

知识是独立表，按平台 → 大陆 → 区域 → 生境分层，小范围覆盖大范围。不要把整棵知识树死写进后裔配置当唯一真源；创生时再注入。

- **require**：这条基因 / 能力要发挥，声明缺哪些键（键 = slug = 后裔 env key）
- **has**：始祖 / 血脉 / 后裔实际有什么，向下继承

两套分开管。创生时 has 盖不住 require 只提示，不阻断——上游不自洽不该把系统卡死。

## 5. 协作：看得见的邻居，而不是会场麦克风

### 5.1 兽道

能说话的集合由兽道显式画出来。人在领地地图上连线、拆线、移动。发光跟着后裔心智状态走，这是旗舰面，不是装饰。

没有兽道时，人类 `@` **不得**偷偷打到对方 Host。那会把「没连上」伪装成「已经传过去了」。正确路径是小脑（审计 + Composer 引导）；现在业务小脑仍是模板 / 只 notify，这是已知缺口，不是设计允许静默代理。

禁止生境级 Agent 广播总线。jcode 只借 soft interrupt、typed handoff、file-touch，不借频道、全场广播、千员 swarm。

### 5.2 投递三态

往正在跑的后裔塞东西，要说清楚会不会打断它：

| 模式 | 含义 | 为什么要有 |
|---|---|---|
| `notify` | 留线索，不打断，不单独叫醒空闲轮 | 旁观 / 记录 |
| `soft_inject` | 在 Host 安全点插入（工具结果齐了、下一次模型调用前） | 协作但不撕当前工具批次 |
| `wake` | 空闲则开一轮；已经在跑则降成 soft_inject | 明确叫醒；硬中断仍走 `/interrupt` |

注入入口和控制出口成对：既能把基因 / 能力打进去，也能 pause / resume / snapshot。后裔用 tool 调后端上报粮仓、拓扑、结构化 report，而不是在 pod 里自己发明第二套总线。

### 5.3 信号塔为什么是四块

每个生境一座信号塔，不是「再造一个群聊」：

| 区 | 干什么 | 设计理由 |
|---|---|---|
| **粮仓** | 正在用的共享文件。`shared/` 是挂载；`work/` 是私有临时区，做完迁进共享 | 不要再造一套重型 DB 虚拟文件系统当唯一真相；人必须能在 Portal 里 CRUD 目录 |
| **额叶** | 看板 | 工作可见 |
| **脑干** | 调度 / 定时 / 会议唤醒 | 产品面要真能点，不能 501 |
| **小脑** | 系统智能体 | 见下 |

**标本**是冷归档（现在用数据库键值就够，对象存储以后再说），不要和粮仓抢「正在用」的语义。

**小脑**按**区域**一条血脉（`is_cerebellum`），不进普通血脉列表：第一个生境创生血脉 + 后裔，之后的生境只给同一条血脉再开后裔。场景级身份跨该场景的多条工作流复用；真正干活、接需求和回结论的，是 **这片生境里的小脑后裔**。概念上信号塔连得动所有 pod，但 **prompt 禁止越权传话**。远期工单入口里，需求交给这只生境小脑，其它角色 harness 协同，收口也由它回结论——小脑是收口角色，不是广播总机。

**星球中枢（现在）**是大陆级短会话（写描述、给默认模型），不是小脑。一个是真 harness，一个是带提示词的短处理。

**星球中枢（远期，§10.3）**可以升成「看工单、生成网络、拉起部署」的大陆入口，仍然 **不是** 生境里那只小脑。中枢搭网；小脑收口。

## 6. 谁能进这座大陆

权限不靠「管理员 / 编辑」这种静态 role 列（已经物理删掉）。拆成三层，免得目录和授权缠在一起：

1. **智人基因**只描述原子 `can_*`（目录中性，不表示某人拥有它）
2. 界面上的「基因组」只是表单多选，展开后写入原子；后端不建 Pack 表
3. **授权**写在大陆成员关系上：没有这一行，这座大陆对你不存在；原子数为 0 等于没加入。区域成员在此之上并集细化，v4 不做 deny-list

超管 `is_super_admin` 只是平台破例，不替代日常授权。登录先选大陆；可以自建大陆（创建者拿到 owner 那包原子）。没有邮件邀请也能把已注册用户拉进来赋基因——先闭环，邀请系统以后再说。

系统预置（始祖 / 基因 / 知识 `scope=system`）全大陆只读可见，不进「商店售卖」，也禁止一般用户改 scope。列表默认看见「当前区域 ∪ 大陆 ∪ 系统」；新建默认落在大陆。

**副本**：大陆 / 区域结构 / 始祖 / 血脉可以深拷贝绑定；**后裔不可拷贝**——拷的是拓扑座位，身体要重新创生、部署。别人的成员关系不跟着大陆副本走。

## 7. 经验怎么回去

记忆只追加、挂在血脉上。Harness 的 notepad 和记忆合成同一套叙事，不要两套互不相认的「笔记」。

两条链必须分开。曾经有过「四级跳」把内容升级和身份升级揉在一起，那会逼每一次领悟都改身份，或每一次蜕变都发明新始祖：

```
内容：记忆 ──领悟──▶ 能力 ──打包──▶ 生物基因
身份：后裔 ──蜕变──▶ 血脉 ──演化──▶ 始祖
```

蜕变要把运行期长出来的绑定（含 has 知识）写回血脉。演化生成的新始祖默认落在大陆，并带走基因和 has 知识。走内容链时，运行中的后裔绑定要同步更新，否则「市场上有了，身上没有」。

## 8. 界面怎么铺

登录 → 选大陆 → 大陆首页。区域页只管这个场景里的生境 / 血脉 / 后裔 / 成员，不再把始祖商店、能力市场、Debug 塞进区域六个 tab——那些是大陆级目录。

现在，生境 IDE 才是干活的地方：领地地图 + Composer + 信号塔 + 后裔控制。拓扑不做区域侧栏聚合；把所有生境压进一张图，会毁掉「近邻」的空间直觉。

远期可以多一个 **工单入口**（§10.3）：提单人不必先学会画兽道。操作员控制台仍在，权可以分开。

路由是路径式 `/orgs/:orgId/...`，切换大陆就进目标大陆首页。旧 URL 重定向，不 404。

## 9. 运行时：协议中立，身体不热切换

Tunnel WebSocket 是后裔的公共接入面：信封中性，pi 的内部事件在 Host 里消化，不进协议。控制动作用 interrupt / pause / resume 这类中立词，不把 `kill` / `abort` 泄漏成产品协议。

runtime 在创生或外接时绑死。**同一个后裔生命周期内不热切换**——热切换会让「这个身体是谁」变得不可审计。要换引擎，走以后定义的重新物化，不在原地重绑。

**不预建** runtime 接口基类、adapter 市场、插件平台。第二种 runtime 真正要被管理层接管时，以现在的 pi Host 为模板做第二个接入，再从差异里抽最小抽象。

后裔是 K8s 上能重启、能看日志、能走九步诞生管线的对象，不是状态徽章。测试环境钉在 orbstack 的 `eyot` 命名空间，改了代码就要重新部署上去给人看——这是产品约束，不是运维偏好。

## 10. 现在做什么，以后做什么

版本在 0.x。功能收口（v4）和命名 / 视觉（v5）已经交付。当前程序是 **对照设计把已有面跑通**：中枢 → gene → 协作。没有提案，不升号、不开新视觉世代。

### 10.1 近期，但有门禁

**Composer 多模态 + 富文本**：在现有 Composer / Tunnel 上补模态和渲染。会做，必须等上面三层稳定。这不是会话引擎重建。

开工前还要单独锁：image 是否 day-1、音视频是否同切片、富文本只渲染还是可编、是否写入 transcript。

### 10.2 远期：会话引擎 v2

用户原话大意：会话这块要更轻、更好用；功能以后都要有（Tunnel、Voice、Channel 那一类表面）；**image / audio / video 要在搭建时就做成协议一等公民**，走 LLM 原生多模态，不要事后把 base64 塞进字符串。

所以这是整包重建（更轻的会话存储、协议 day-1），不是在现在的 Zustand 大 store 上继续补丁。搭建时锁定，不能后补。未开提案前不当开工。

### 10.3 远期：工单入口（分权 + 中枢搭网 + 小脑收口）

当前产品默认操作员进领地地图，自己创生、连兽道、说话。远期希望 **对用户分权**：一部分人不必拥有整张控制台，只提交工单。

主路径（未开工，提案前要锁 schema / 权限原子 / 失败回滚）：

```
提单人提交工单
  → 星球中枢按工单生成一套网络（生境 + 座位 + 该出场的角色 harness）
  → 搭建并部署后裔
  → 把需求交给这片生境的小脑后裔
  → 其它角色 harness 按兽道做 loop engineering
  → 任务结束：小脑回一个结论给提单人（操作员仍可打开领地地图审计）
```

这可以成为 **另一个主入口**，不是把 IDE 拆了。和现在设计的衔接：

- 组出来的仍是生境 + 兽道 + 角色后裔，不是临时群聊总线。
- 小脑仍是「区域一条血脉、生境一只后裔」；工单落在某片生境上，收口的是那只后裔。
- 星球中枢负责 **生成和部署网络**，不代替角色 harness 干活，也不全场广播。
- 分权走现有智人基因原子（例如将来的提单 / 只读结论 / 全权调度），不重新发明静态 role。
- 其它 harness 的协同仍走投递三态和兽道；做完由小脑收口，避免「谁都能代表任务结束」。

未决（开工前锁）：工单是否落成独立表、网络是新建生境还是复用模板生境、失败是整网 teardown 还是留半成品、结论是一段话还是带粮仓产物。未锁之前不当实现。

这和会话引擎 v2、Composer 多模态都不是同一张切片。

### 10.4 远期：外接后裔

除了 Eyot 托管拉起的沙箱，还要能 **attach** 已经在本机或远程跑着的 runtime（先瞄准 pi）。逻辑执行体仍是后裔，不新造一种「外接实体」。

本机目录不是 attach 的附赠礼物：要显式授权、可撤销、可审计。远程 runtime 默认碰不到操作者的磁盘；需要挂载、同步或文件桥。先用一个真场景验证语义，再抽抽象。

### 10.5 明确暂缓或拒绝（相对 nodeskclaw）

| 方向 | 态度 | 原因 |
|---|---|---|
| Voice | 暂不做 | 不在当前规划；真做会进会话引擎 v2 的协议窗口 |
| 节点级 Channel（飞书 / Discord…） | 不做 | 不必给每个节点加频道；最多将来在 Composer 做输入输出通道 |
| 运行期模型发现 | 不做 | 先静态配置智能（Provider） |
| 知识 scope | 不移植对面 | Eyot 已有独立表 + 覆盖链 |
| 邮件 / SMS 邀请、配额 | 不做（当前） | 先用「已注册用户 + 赋基因」闭环 |
| RAG / 向量库 | 不做（当前） | 知识是绑定和覆盖，不是检索产品 |
| 后裔拷贝 | 永久拒绝 | 身体不可复制；复制的是座位 |
| 生境广播总线 | 永久拒绝 | 近邻是身份 |
| subagent 变成地图节点 | 永久拒绝 | 没有长久记忆就不要占拓扑 |

小脑「没有兽道时 `@` 转真实业务」仍是模板。要做须单独提案，不能用 subagent 顶替。

能力中枢「帮人写 skill」、Gene 级 LLM 真蒸馏、OTel / 备份 / S3 标本，都是以后的增强，不是固化程序自动吞进去的范围。

## 11. 设计时反复用来做判断的几句话

- Eyot 是 harness for harness：外层组网，内层每只后裔是一个按角色装好的 harness 入口。
- 后裔的基因 / 能力要够这份角色把一串任务做完；harness 结构按这类任务来装，不是通用聊天再贴人设。
- 地方是场景，生命是身份；后裔只是这一次跑起来的身体。
- 没有长久记忆，就不要命名、不要占地图。
- 能说话的集合必须画得出来；画不出来就不能假装送到了。
- 真源只有一份：绑定、合同、知识表；JSON 覆盖不是第二份产品。
- 协议中立、身体不热切换；第二种 runtime 用真实差异来抽，不预建平台。
- 中枢搭网，小脑收口；不要让星球中枢去干角色 harness 的活，也不要全场广播。
- 单租户永远合法；多大陆是能力，不是门槛。
- 做深不做宽：先把中枢、基因、协作跑成它说的那样，再谈多模态、会话重建和工单入口。
